    test(fr09): add 18 data-driven coupon test cases

    Covers the percent and fixed calculation matrix, the minimum-order
    boundary, unusable codes, code normalisation, the per-user usage limit,
    the full customer journey from product to payment, and two invariants that
    must hold for every coupon.

    Six tests are tagged @bug. The heaviest is the percent formula: server.js 
    computes total*(1-discount_value) instead of total*discount_value/100, so
    a 10% coupon on a 500,000 order returns a discount of -4,500,000 and a
    payable of 5,000,000 while the UI still shows a green tick and "Giảm 10%".

    TC-18 asserts invariants rather than specific figures - no discount may be 
    negative and no discounted total may exceed the original - because an 
    invariant also catches variants of the fault that a fixed expected value 
    would miss.

    The cart is plain React state with no persistence, so a full page load 
    empties it. The end-to-end case therefore navigates by clicking, while the 
    calculation cases go straight to checkout and drive the editable total.
